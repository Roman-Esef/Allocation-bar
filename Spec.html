Summary Breakdown Widget

Универсальный компонент для отображения итогового числового значения и его детализации по составляющим. Не привязан к доменной области — используется для финансовых сумм, количества штук, документов, сделок или любых других агрегируемых величин.

01Обзор компонента

Принцип универсальности. Компонент не знает, что такое «кредит» или «акции». Он принимает массив items[] с произвольными лейблами и значениями. Все доменные термины приходят снаружи как props.

Где применяется. Карточки на дашборде, сайдбары детализации, виджеты в модальных окнах и аккордеонах. Не подходит для случаев, где нужна сортировка пользователем, drill-down или редактирование значений — см. раздел 12.

1.1Анатомия

Размеры в фиолетовом — отступы и высоты в пикселях. Серые выносные линии указывают на элементы компонента. Числовые колонки выровнены по правому краю; tabular-nums гарантирует, что цифры не «прыгают» при смене значения.

Четыре комбинации флагов showPercent и showProgressBar покрывают разную плотность данных. По умолчанию активны оба — это рекомендуемый режим.

04Состояния компонента

Состояние — это атомарный status + три производных от данных: partial (сумма позиций < total), overflow (сумма > total), zero item (позиция со значением 0).

Loaded
status: "loaded"
Loading — fast (< 3 сек)
status: "loading"
Полный скелетон: total, бар и строки. Используется при коротких ожиданиях (до 3 секунд) — не отвлекает пользователя текстовыми пояснениями.
Loading — slow (≥ 3 сек)
loadingVariant: "slow"
Когда вычисление дольше 3 секунд — скелетоны только у total и прогресс-бара, а вместо строк появляется плашка «Данные рассчитываются · Это может занять несколько секунд». Так пользователь понимает, что ожидание оправдано.
Error
status: "error"
Иконка + краткое сообщение + кнопка «Повторить». Не показываем стек или код ошибки в UI.
Empty
status: "empty"
Partial (сумма < total)
25 + 25 + 25 = 75%
Остаток показывается серым «остатком» в баре, в подвале — поясняющий текст.
Overflow (сумма > total)
50 + 40 + 25 = 115%
В подвале — предупреждение. Бар нормализуется по сумме, но цвет подвала сигнализирует о проблеме.
Zero item (одна из позиций = 0)
item.value: 0
Позиция отображается, но в баре её сегмент не виден. Это нормально: пользователь видит, что показатель учтён, но равен нулю.

Правила назначения

Цвет берётся по индексу позиции: первая позиция → Indigo, вторая → Mint, и т. д. Это значит, что у одной и той же сущности (например, «Кредит») цвет может отличаться в разных виджетах — это намеренно. Если консистентность важна, передавайте items[].color явно.

Поведение при 9+ позициях

Палитра не циклится. С 9-й позиции включается стратегия group-into-other: девятая и далее объединяются в одну виртуальную позицию «Прочее» цвета Slate (08). Это сохраняет визуальную читаемость бара и предотвращает повторение цветов.

06Поведение прогресс-бара

Минимальная ширина сегмента

Сегмент менее 2px невозможно различить на экране. Через ResizeObserver компонент гарантирует min-width: 2px для каждого ненулевого сегмента — остаток ширины распределяется пропорционально между остальными.

Доминирующая позиция 99,7%
бывший «малый» сегмент остаётся видимым

Скругления, gap, hover-связь

  • Скругление: border-radius: 999px на контейнере, сегменты обрезаются через overflow: hidden. Первый и последний сегменты получают скругление автоматически.
  • Gap: 2px между сегментами — даёт визуальное разделение без потери компактности.
  • Hover-связь: при наведении на сегмент остальные приглушаются (opacity: 0.55), при наведении на строку — приглушаются все сегменты кроме связанного.
  • Tooltip: по title атрибуту — на нативном механизме браузера. В сложных лейаутах можно подключить кастомный tooltip-компонент.
Hover: попробуйте навести на сегмент или строку

07Адаптивность и контейнерные ограничения

i
Компонент адаптируется к ширине своего контейнера, а не вьюпорта. Это значит, что один и тот же виджет на широком экране в узком сайдбаре ведёт себя как на мобильном — он «знает» сколько у него места локально. Реализуется через container-type: inline-size и CSS Container Queries; для пересчёта ширины сегментов бара — ResizeObserver.

7.1Адаптивность по ширине

Четыре контейнерных брейкпоинта: широкий (> 480px), средний (320–480px), узкий (< 320px), деградация (< 160px).

Широкий — > 480px (базовый вид)

container: 540px

Всё отображается: label · percent · value в одной строке, числа выровнены по правому краю, dot-маркер 8px, total 18px.

Средний — 320–480px (компактный)

container: 400px
  • Long-label позиций обрезаются с ... + tooltip при hover
  • Total уменьшается до 16px, шрифт строк — до 13px
  • Колонки percent и value сближаются (min-width: 56 / 64px)
  • Unit можно сократить (передаётся в prop как короткая строка)

Узкий — < 320px

container: 280px
  • Колонка percent скрывается принудительно
  • Прогресс-бар сохраняет базовую высоту 8px — никогда не утончается
  • Строки переходят в двухстрочный режим: label сверху, value снизу
  • Total — 15px

Очень узкий — < 200px

container: 200px

Видны только label и total. Детализация сворачивается за триггером «Развернуть» — разворачивается в всплывающий попап (controlled через aria-expanded).

Деградация — < 160px

container: 160px

7.2Адаптивность по высоте — ограниченный контейнер

Реальный кейс: виджет помещён в карточку с фиксированной высотой, и список позиций не помещается. Поведение зависит от того, насколько сильно ограничен контейнер.

Сценарий A — контейнер чуть меньше нужного

1–2 строки не влезают. Снизу появляется fade-градиент, затухание подсказывает что контент продолжается. Под fade — ссылка «Ещё N позиций».

height: 140px · item count: 8
Ещё 4 позиции →

Сценарий B — влезает только заголовок + бар

Детализация полностью скрыта. На прогресс-бар при hover — tooltip с мини-списком всех позиций (label + %).

height: 70px

Сценарий C — не влезает даже бар

Показываются только label + total. Если контейнер ниже 60px — компонент рендерит заглушку с иконкой; ниже 48px компонент не должен использоваться.

height: 48px
i
Иерархия приоритетов при ограничении высоты:
total — никогда не обрезается · bar — может исчезнуть вторым · items — исчезают первыми

7.3Поведение при растяжении

Когда компонент попадает в «резиновую» сетку, у него есть рекомендация max-width: 600px. Это не жёсткое ограничение — разработчик может его переопределить, но дефолт защищает от антипаттерна бесконечно растянутых строк.

Правильно good
бар + total — full width · список ограничен 600px
Прогресс-бар и total занимают всю ширину контейнера — они хорошо считываются на любом размере. Список параметров ограничен 600px от левого края, поэтому лейбл и значение остаются рядом. Hover-фон строки заливает всю ширину, текст внутри не разъезжается.
Антипаттерн avoid
всё растянуто на 100%
Строки тоже растянуты — значение «511,60» далеко справа от лейбла «Кредит», связь визуально разрывается.

7.4Компонент в специфических лейаутах

В сайдбаре (~240px)

Один из самых частых кейсов. Прогресс-бар занимает всю ширину; label и value — двухстрочный режим; maxVisibleItems: 3, остальные — «Ещё N».

В модальном окне

Модалка может ресайзиться пользователем — компонент перестраивается через Container Queries автоматически. Показано на двух типичных ширинах:

В коллапсируемой секции (аккордеон)

Когда секция закрыта — компонент не рендерится (или рендерится с visibility: hidden, чтобы быть доступным для screen reader). После открытия ResizeObserver пересчитает ширину сегментов на следующем кадре.

7.5Поведение при динамическом изменении размера

Реальный кейс: пользователь двигает сплиттер между панелями. Компонент должен плавно перестраиваться без мерцания.

  • Пересчёт ширины сегментов — через ResizeObserver, не через resize-event окна
  • Структурные изменения (скрытие колонки, двухстрочный режим) — мгновенно, без transition
  • Размерные изменения (font-size, dot, padding) — transition: 150ms ease
  • Пока ResizeObserver ещё не сработал — рендерится промежуточное состояние с visibility: hidden на баре, total и заголовок видны сразу

7.6Контентно-зависимые ограничения

Очень длинный sublabel

Sublabel — одна строка, обрезается с .... Полный текст доступен через title-tooltip. Перенос в две строки не используется — нарушает вертикальный ритм.

Очень большое число в total

Числа выше 999 999 999 — переходим на компактный формат через SummaryBreakdown.fmtCompact(): 1,5 млрд вместо 1 500 000 000. Шрифт total использует clamp(15px, 1.4cqi + 8px, 22px) — fluid typography от ширины контейнера. Включается через prop format: "compact".

Смешанные длины label у позиций

Колонка label обрезается по доступной ширине, не растягиваясь под самый длинный лейбл. Числовые колонки всегда выровнены по правому краю.

7.7Accessibility при ограниченных размерах

  • Скрытые через overflow элементы доступны screen reader — используется visibility: hidden или aria-hidden="false"; не display: none для строк под fade-градиентом
  • Триггер сворачивания/разворачивания имеет aria-expanded и aria-controls
  • Прогресс-бар имеет role="img" и aria-label с текстовой сводкой всех позиций
  • Tooltip при hover дублируется при focus — клавиатурный доступ обязателен
  • Touch-таргеты («Показать ещё», иконка expand) — минимум 44×44px даже в самом узком контейнере
  • Сегменты бара не являются интерактивными элементами по умолчанию — это decorative graphics; для интерактивности оборачивайте в <button>

★Интерактивный демо

Двигайте ползунок ширины — или потяните за правый край контейнера — чтобы увидеть, как компонент проходит брейкпоинты в реальном времени.

11Checklist для разработчика

  • Компонент использует Container Queries, не Media Queries
  • ResizeObserver подключён для динамического ресайза сегментов бара
  • При ширине < 320px проценты скрываются автоматически
  • При overflow контейнера по высоте — появляется fade + «Ещё N»
  • total никогда не обрезается и не скрывается
  • Прогресс-бар пересчитывает сегменты после того как контейнер стал видим
  • Все скрытые элементы (под fade, в свёрнутом списке) доступны через screen reader
  • Числа форматируются через Intl.NumberFormat('ru-RU'), не вручную
  • Цвета берутся из палитры по индексу; 9-я позиция и далее → «Прочее»
  • Минимальная ширина сегмента бара — 2px (через ResizeObserver-постпроцессинг)
  • Состояния loading / error / empty имеют отдельные визуальные ветки, не overlay поверх loaded
  • Hover на сегменте бара или строке — двунаправленная связка через opacity
  • Touch-таргеты ≥ 44×44px (включая «Показать ещё» и expand-триггер)
  • Локаль форматирования передаётся как prop, дефолт — ru-RU

12Что намеренно НЕ входит в компонент

Чтобы оставаться универсальным и простым, компонент не делает следующее. Если вашему сценарию это нужно — оборачивайте Summary Breakdown в композитный компонент уровня вашей продуктовой команды, не модифицируйте сам виджет.
